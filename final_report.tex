\section{Problem Description}
% ===========================================================================

Stereo vision recovers scene depth from two cameras with a known horizontal
baseline. Given a \emph{rectified} pair of images---left $I_L$ and right
$I_R$, in which a 3D point projects to the same scanline in both views---the
task is to find, for every pixel $(r,c)$ in the left image, the horizontal
\emph{disparity} $d$ such that $I_L(r,c)$ matches $I_R(r,c-d)$. Disparity is
inversely proportional to depth ($Z = fB/d$ for focal length $f$ and baseline
$B$), so a dense disparity map is a dense depth map.

\paragraph{Inputs and outputs.} The input is a rectified 8-bit grayscale
stereo pair of size $H\times W$ and a maximum disparity $D_{\max}$. The output
is a dense disparity map $D(r,c)\in[0,D_{\max})$, stored as 32-bit float so we
can represent sub-pixel disparities. We assume the pair is rectified (search is
purely horizontal) and that disparity is non-negative (the right view is
shifted left of the left view). These are the standard assumptions of the
Middlebury benchmark~\cite{scharstein2002}.

\paragraph{Why it matters and why multi-GPU.} Depth perception is the input to
obstacle avoidance, mapping, and manipulation in robotics. A robot with several
stereo heads must produce depth at the camera frame rate (30--60\,Hz) and at
high resolution. The cost of dense matching is
$\Theta(H\,W\,D_{\max}\,(2R{+}1)^2)$ for a patch radius $R$: a single
$1920\times2560$ pair with $D_{\max}=64$ and $R=2$ is already
$\sim 16$ GOps \emph{per frame} (Sec.~\ref{sec:model}). Several cameras at high
resolution and frame rate exceed a single GPU's budget once additional
processing (rectification, post-filtering, tracking) shares the device, and the
cost volume for large images can exceed one GPU's memory. Distributing the
image across GPUs with MPI both shrinks per-GPU compute and per-GPU memory,
which is exactly the regime a multi-camera rig operates in.

\section{Algorithms and State of the Art}
% ===========================================================================

Dense two-frame stereo is classically organized into a four-stage
pipeline~\cite{scharstein2002}: (i) compute a matching \emph{cost} for every
pixel and candidate disparity; (ii) \emph{aggregate} cost over a support
region; (iii) select a disparity; (iv) refine. Methods differ mainly in stages
(ii)--(iii).

\paragraph{Local block matching (our baseline).} The simplest aggregation sums
a per-pixel cost over a fixed square window and picks the per-pixel
winner (winner-take-all, WTA). With the sum-of-absolute-differences (SAD) cost,
\begin{equation}
\label{eq:sad}
\mathrm{SAD}(r,c,d) \;=\!\!\! \sum_{\substack{|i|\le R\\ |j|\le R}}
\bigl| I_L(r{+}i,\,c{+}j) - I_R(r{+}i,\,c{+}j{-}d) \bigr|,
\qquad
D(r,c) = \arg\min_{d} \mathrm{SAD}(r,c,d).
\end{equation}
Local SAD is fast and embarrassingly parallel but blurs depth edges and fails
in textureless or occluded regions, because every pixel is decided
independently. This is the algorithm behind OpenCV's
\texttt{StereoBM}~\cite{opencv}.

\paragraph{Semi-Global Matching (SGM).} SGM~\cite{hirschmuller2008}
approximates a 2D global smoothness energy by summing 1D dynamic-programming
problems along several image directions. Along a path direction $\mathbf{r}$,
the aggregated cost obeys the recurrence
\begin{equation}
\label{eq:sgm}
L_\mathbf{r}(\mathbf{p},d) = C(\mathbf{p},d) + \min\!\Bigl(
L_\mathbf{r}(\mathbf{p}{-}\mathbf{r},d),\;
L_\mathbf{r}(\mathbf{p}{-}\mathbf{r},d{\pm}1){+}P_1,\;
\min_k L_\mathbf{r}(\mathbf{p}{-}\mathbf{r},k){+}P_2\Bigr)
- \min_k L_\mathbf{r}(\mathbf{p}{-}\mathbf{r},k),
\end{equation}
where $P_1$ penalizes $\pm1$ disparity steps (slanted surfaces) and $P_2>P_1$
penalizes larger jumps (depth edges). The final cost $S(\mathbf{p},d)=\sum_\mathbf{r}
L_\mathbf{r}(\mathbf{p},d)$ is minimized over $d$. SGM is the accuracy/speed
sweet spot used in production: OpenCV \texttt{StereoSGBM}, NVIDIA
VPI~\cite{nvidiavpi}, and the open-source real-time GPU implementation
\texttt{libSGM}~\cite{hernandez2016} all use it, typically with 4 or 8 paths
and a Census-transform cost~\cite{zabih1994}. State-of-the-art accuracy today
comes from deep networks (e.g.\ PSMNet, RAFT-Stereo)~\cite{chang2018}, but
these are heavier and outside the scope of a CUDA+MPI systems study.

\paragraph{What we built and why.} We implemented (1) local SAD in three CUDA
variants of increasing optimization, (2) two accuracy add-ons---parabolic
sub-pixel refinement and a left--right consistency (LRC) check---and (3) a
4-path GPU SGM that reuses the \emph{same} SAD window as its data term
$C(\mathbf{p},d)$. Using an identical data term isolates the effect of the
aggregation strategy, letting us compare local WTA against semi-global
optimization on equal footing. We chose 4 paths (left$\rightarrow$right,
right$\rightarrow$left, top$\rightarrow$bottom, bottom$\rightarrow$top) rather
than 8 because the four axis-aligned paths capture most of the benefit while
mapping cleanly to coalesced memory access (Sec.~\ref{sec:parallel}); the
diagonal paths of full 8-path SGM stride awkwardly across rows.

\section{Parallelization Strategy (CUDA + MPI)}
\label{sec:parallel}
% ===========================================================================

\subsection{CUDA kernels and the memory hierarchy}

Every kernel assigns one thread to one output pixel and loops over $D_{\max}$.
The interesting design axis is how the heavily reused right-image pixels are
fed to the ALUs.

\begin{itemize}
\item \textbf{\texttt{basic}}: a direct translation of Eq.~\eqref{eq:sad}. Each
thread reads its patches straight from global memory for every disparity. All
reuse is implicit, through the L2 cache.
\item \textbf{\texttt{smem}}: a $16\times16$ thread block cooperatively stages
the left tile $(B{+}2R)^2$ and the right tile $(B{+}2R{+}D_{\max})$ into shared
memory once, then every thread reads its windows from shared memory. Loads are
coalesced and each global byte is reused $\sim B^2$ times.
\item \textbf{\texttt{tiled}}: each thread keeps a private register array
\texttt{sad[64]} and accumulates all $D_{\max}$ costs while sweeping the window
\emph{once}. A left pixel, loaded once, is reused across all 64 disparities, and
the inner disparity loop is fully unrolled.
\end{itemize}
The tiled kernel also performs the parabolic sub-pixel step at no extra memory
cost because the whole cost curve is already in registers:
$d^\star = d - \tfrac12\,(S_{d+1}-S_{d-1})/(S_{d-1}-2S_d+S_{d+1})$.
The LRC check runs the tiled kernel a second time with the roles of the images
swapped and rejects pixels whose left- and right-referenced disparities
disagree by more than one pixel.

For SGM the cost volume is laid out as \texttt{C[(r*W+c)*D + d]} so that the
$D$ threads of an aggregation block access \emph{contiguous} memory. Each
aggregation kernel launches \textbf{one block per scanline} with $\mathrm{next\_pow2}(D)$
threads: the SGM recurrence~\eqref{eq:sgm} is a serial dependency \emph{along}
the path, so a block walks its scanline step by step, while the $H$ (or $W$)
independent scanlines run in parallel across blocks. The $\min_k$ term is a
shared-memory tree reduction over the previous pixel's costs. Four launches
accumulate into $S$; a final kernel does WTA + sub-pixel.

\subsection{MPI decomposition and communication}

We use a 1-D \textbf{row decomposition}. For $P$ ranks, rank $i$ owns
$h_i=\lfloor H/P\rfloor + [\,i < H \bmod P\,]$ consecutive rows, so work is
balanced to within one row. The decisive argument for rows over columns is
\emph{halo asymmetry}: the SAD window needs $R$ neighbouring rows, but because
the disparity search is horizontal, a column split would need a halo of width
$D_{\max}+R$ on each side. With $R=2$ and $D_{\max}=64$, a row halo is 2 rows
while a column halo would be 66 columns---a $33\times$ larger exchange. Row
decomposition makes the halo essentially free (Sec.~\ref{sec:bottleneck}).

Each rank therefore needs only its owned rows plus an $R$-row halo above and
below. The communication pattern is three operations:
\begin{enumerate}
\item \texttt{MPI\_Scatterv} sends each rank only its owned rows of $I_L$ and
$I_R$ from rank~0 (variable counts handle the non-divisible case).
\item \texttt{MPI\_Sendrecv} exchanges the $R$ halo rows with the two
neighbouring ranks (point-to-point, no root involvement).
\item \texttt{MPI\_Gatherv} collects the owned disparity rows back to rank~0.
\end{enumerate}
This replaces the full-image broadcast of our Milestone~4 prototype, which sent
every rank the entire image. Each rank maps to a GPU with
\texttt{cudaSetDevice(rank \% num\_devices)}; on our 4-GPU node ranks 0--3 use
four distinct GPUs. Host buffers are page-locked with \texttt{cudaHostRegister}
and copied with \texttt{cudaMemcpyAsync} on a dedicated stream so transfers use
true DMA. We report the slowest rank's kernel time via
\texttt{MPI\_Reduce}/\texttt{MPI\_MAX}, since the distributed run is limited by
the straggler.

\section{Performance Model}
\label{sec:model}
% ===========================================================================

\paragraph{Roofline / arithmetic intensity (single GPU).}~\cite{williams2009} Each output pixel
performs $2(2R{+}1)^2 D_{\max}$ integer ops (one subtract-abs and one add per
window element per disparity). In the worst case (no reuse) it loads the same
number of bytes, since pixels are 8-bit:
\[
\text{ops} = \text{bytes} = 2(2R{+}1)^2 D_{\max}
\;\Rightarrow\;
\text{OI}_{\text{naive}} \approx 1~\text{op/byte}.
\]
On a Quadro RTX 6000 (Turing, 4608 cores, $\sim$16.3 TFLOP/s FP32-class
throughput, 672 GB/s DRAM, 6\,MB L2) the roofline ridge point is
$16{,}300/672 \approx 24$ op/byte. Since $\text{OI}_{\text{naive}}=1 \ll 24$,
\textbf{the model predicts SAD is strongly DRAM-bandwidth-bound}, with a naive
ceiling of $\sim$672 GOps/s. The falsifiable prediction: a kernel that does not
improve reuse cannot exceed $\sim$0.7 TOps/s, and any kernel that does should
scale with how much reuse it extracts from the on-chip hierarchy (L2 $\to$
shared memory $\to$ registers).

\paragraph{Communication model ($\alpha+\beta n$).} A rooted collective moving
$n$ bytes costs $\approx \alpha + \beta n$. In our scheme the per-rank scatter
and gather payloads are $\tfrac{H}{P}W$ bytes, but they pass through rank~0,
whose link is shared, so the \emph{root} moves $\Theta(P)\!\cdot\!\tfrac{H}{P}W
= \Theta(HW)$ bytes regardless of $P$ and serializes them. The model therefore
predicts (i) halo cost stays negligible and constant, and (ii) scatter+gather
time \emph{grows} with $P$ even though each rank's own slab shrinks---the source
of strong-scaling loss.

\paragraph{Amdahl prediction (strong scaling).} Writing the wall time as
$T(P)=T_{\text{comp}}/P + T_{\text{comm}}(P) + T_0$ with a near-serial overhead
$s=(T_{\text{comm}}+T_0)/T(1)$, larger images (larger $T_{\text{comp}}$) have a
smaller $s$ and must scale better. From the measured single-rank split this
predicts $1920\times2560$ should scale markedly better than $960\times1280$,
which in turn beats the $480$-row case---a prediction we test next.

Two predictions of the roofline model are confirmed and one is refined
(Fig.~\ref{fig:roofline}). (1) The
ordering is set entirely by data reuse, not arithmetic---exactly what a
memory-bound kernel should show. (2) Even \texttt{basic} reaches 996 GOps/s,
\emph{above} the 672 GOps/s DRAM ceiling: the right-image reads of adjacent
threads and disparities overlap heavily and are served from L2, so the
\emph{effective} bandwidth exceeds DRAM. The refinement: the relevant ceiling is
the L2/shared-memory bandwidth, and \texttt{smem} wins by turning implicit L2
reuse into explicit, conflict-free shared-memory reuse. This is the GPU
memory-hierarchy story from lecture made quantitative. \texttt{smem} is the
fastest single-image kernel; \texttt{tiled} is used in the MPI driver because
its single-pass register accumulation behaves best on tall, narrow slabs and
carries the sub-pixel/LRC logic for free.

The three methods are three points on an accuracy/cost/density curve. Local SAD
is fastest ($\sim$0.2\,ms) and dense but error-prone (13--20\% bad). LRC roughly
halves the error by \emph{rejecting} unreliable pixels, trading 11--18\% of
coverage for cleanliness; it changes the bottleneck from matching quality to
density. SGM roughly halves the bad-pixel rate \emph{at full coverage} by
propagating support along scanlines, at $4\!-\!6\times$ the cost of tiled SAD
and $\sim$3$\times$ the cost of LRC. On \texttt{tsukuba} and \texttt{venus} SGM
is the clear accuracy winner; on \texttt{sawtooth}, whose errors are
concentrated in occlusions, LRC's outright rejection scores lower bad-px but
only by discarding pixels. This is the central algorithmic finding: \emph{which
variant to deploy depends on whether the downstream consumer wants dense depth
(SGM) or sparse-but-trustworthy depth (LRC)}.

\subsection{Strong scaling}

fixed image sizes on 1/2/4 GPUs. The GPU \emph{kernel} time scales almost

scales better: 4-rank wall efficiency is \textbf{85\%} for $1920\times2560$ but
\textbf{68\%} for $960\times1280$, because the bigger image gives each GPU
enough work to amortize the fixed communication overhead.

\subsection{Weak scaling}

For weak scaling we fix 480 rows per rank ($W{=}1280$) and grow the image with
$P$. Table~\ref{tab:phases} already gives the phase data; Fig.~\ref{fig:weak}
plots efficiency. The kernel time is \textbf{flat} at $0.99$\,ms across 1/2/4

weak efficiency stays high (91\% at 4 ranks); the only erosion is the rooted
scatter/gather, whose volume through rank~0 grows with $P$ as the model
predicts. \emph{Isoefficiency:} to hold efficiency constant we must grow the
total problem so per-rank compute keeps pace with the $\Theta(P)$ growth of
root communication---i.e.\ the per-rank slab (not just the total image) should
grow, consistent with the strong-scaling observation that bigger images scale
better.

\section{Discussion, Limitations, and Future Work}
% ===========================================================================

\paragraph{Biggest payoffs.} Two changes gave the most return for the
complexity. First, shared-memory tiling ($2.0\times$ single-GPU speedup) by
attacking the true bottleneck---memory bandwidth---rather than arithmetic.
Second, replacing the Milestone~4 full-image broadcast with
\texttt{Scatterv}+\texttt{Sendrecv}: because the halo asymmetry makes the
neighbour exchange almost free, this removed the $O(P)$ redundant data every
rank used to receive and is what lets the large image hold 85\% efficiency at 4
GPUs.

\paragraph{Not worth the complexity (yet).} The \texttt{tiled} kernel's
register array is slower than \texttt{smem} at small $D_{\max}$ because it always
loops the full 64 slots regardless of the actual disparity range, causing
register pressure; for the real images ($D_{\max}=16$--$20$) a templated
disparity bound would help. Sub-pixel refinement is nearly free but only matters
once disparities feed metric depth. SGM's accuracy is compelling but its
$4\!-\!6\times$ cost and serial path dependency make it the hardest piece to
scale across MPI ranks (paths cross row-slab boundaries), which we did not
attempt.

\paragraph{With more time / hardware.} (1) Overlap communication with
computation by pipelining frames, hiding the rooted scatter/gather behind GPU
work. (2) Use CUDA-aware MPI to eliminate the host staging copies. (3) Replace
the SAD data term with a Census transform~\cite{zabih1994} for robustness to
photometric differences, and extend SGM to 8 paths. (4) Distribute SGM by
exchanging the boundary $L_\mathbf{r}$ frontiers between row neighbours so the
semi-global optimum is preserved across ranks. (5) Benchmark on a multi-node
NVLink/InfiniBand system to see whether the root-collective bottleneck we
identified persists once inter-GPU bandwidth changes.
